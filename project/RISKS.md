# Risk register

Severity: critical / high / medium / low. Status: open / mitigated / accepted / closed.

- R1 (closed 2026-08-25) Scaled-ladder mainnet deploy. Main now defaults to the 0.01..100 ETH ladder; an isolated `testnet` Foundry profile selects the 100x-smaller ladder and separate artifacts, TS fixtures are ladder-specific, and deploy scripts assert the expected compiled profile before broadcast (`ef228f0`, `1020730`). Revalidate those assertions in every release rehearsal.
- R2 (closed 2026-08-25) Loss of uncommitted Surface port. The port was preserved in commit ce4c7e4 before D-04 rejected the architecture and the preservation branch was deliberately deleted with user approval.
- R3 (closed 2026-08-25) Audit findings were historical: audit base 4e6b3d8 predates main's fix wave (a0ff0af..d2f2e59); current main verified fixed. Residue: M-1 into D-08, PoC-to-regression port task. See D-02.
- R14 (closed 2026-08-25) Raised same day on a misread of the stale audit checkout as current main; current settlement is pull-based claimLot, retryable, no lock. Kept as a register entry so the reasoning is not lost.
- R4 (high, open) Irreversible mainnet configuration and key mistakes. `feeBps` and artist are immutable; a reverting fee recipient blocks minting until admin changes it, while renunciation freezes the final recipient; the wrong admin is unrecoverable after renunciation; genesis backing and Shape #0 custody are constructor-time obligations. The one direct artist attestation cannot be replaced, and losing signing capability before it is submitted leaves it unsigned. Mitigation: D-05 key/signing plan, deploy rehearsal, exact release-hash confirmation, recipient receive test before renunciation, and per-broadcast decoded confirmation.
- R20 (medium, open) Compromised admin can redirect future mint-fee revenue. It cannot change `feeBps`, withdraw ETH from Shapes, touch backing/redemption, or seize tokens, but fee redirection is economically meaningful. Mitigation: transfer admin to the D-05 custody target, monitor `FeeRecipientUpdated`, and renounce only when renderer/resolver/copy and the final payout are intentionally frozen.
- R5 (medium, open) ShapeLens/library divergence. No on-chain binding between lens and Shapes linked-library addresses; a mismatched lens silently serves wrong previews. Mitigation: DeployLens.s.sol behavioral probe is mandatory in every deploy path; consider a CI check that recorded addresses match build artifacts.
- R6 (closed 2026-08-27) Site RPC single point of failure. D-12 now gives browser and OG clients one shared fallback policy with an optional configured primary plus three independent public Sepolia providers; deterministic blackhole tests exercise both clients.
- R7 (closed 2026-08-25) Renderer parity drift via WIP. D-03 preserved and reconciled the stale edits; superseded parts were discarded and novel parts became W-1/W-2.
- R8 (medium, open) Vendored OpenZeppelin. Upstream security patches do not auto-propagate. Mitigation: version pin recorded; diff against upstream during P2 audit prep.
- R9 (mitigated 2026-08-27) Direct 10k provenance actions are infeasible: compose is 1.134B gas and direct split/decompose exceed 30M. D-08 proves the same apex through the exact bounded ladder tree, with a 985,862-gas worst individual rung. Residual: production batching remains unmeasured, so the UI must never promise a direct 10k action or an unsupported batch size.
- R10 (low, open) Auction house stray-NFT deposits unrecoverable. Documented and accepted in SECURITY.md; no admin recovery by design. Status: accepted once user reconfirms at P2.
- R11 (low, open) minIncrementBps unbounded uint16. Seller-side only; needs one reviewer pass (D-17).
- R12 (closed 2026-08-25) Repo hygiene debt. The P0 hygiene pass reduced the old checkout to ten justified branches and removed stale worktrees/artifacts with user approval; the canonical clone has one worktree and two local branches.
- R15 (closed 2026-08-27) GitHub Actions resumed after the public-repo cutover. W-4 is now implemented: concurrency cancellation, path-filtered contract/renderer/site jobs, Foundry artifact caches, an explicit site job and the Medusa reserve campaign.
- R13 (medium, open) ERC-8060 draft drift. Implemented against a moving draft; finalization may diverge from the frozen snapshot. Mitigation: re-check draft status at P2; immutable contract means divergence is a documentation/integration issue, not a code fix.
- R16 (accepted 2026-08-26) PR #2 deliberately uses `owner()` for the holder of Shape #0 while `admin()` carries all contract authority. Review confirmed no on-chain authorization defect: every privileged path reads only `admin()`, and ERC-173 is not advertised. Generic selector-only Ownable tooling can still misdescribe the holder, including during escrow or while #0 is absent; this is an integration tradeoff inherent in the explicitly selected product API, not authority to rename it.
- R17 (high, open) The selected architecture is ABI/deployment incompatible with the live Sepolia implementation: payable exact-value constructor, token #0 genesis, public mint start #1, separate admin, removed collector surface, and direct artist attribution. Mitigation: never relabel the old address; the site explicitly tolerates its missing attribution getters, allowing code to merge before the exact `main` commit is deployed fresh. Update addresses/fromBlock only after postflight reads, then rerun all P1 evidence against it.
- R18 (closed 2026-08-26, invalid premise) Adding the intended `owner()` changes the custom `IShapes` ERC-165 fingerprint from `0xbdcee955` to `0x306b220e`. Nothing with the restored architecture has been deployed, no legacy external consumer exists, and no repository production path probes that custom id. The change is expected interface evolution, not a compatibility risk. D-25 is invalidated.
- R19 (mitigated 2026-08-26) Artist signature replay, signer incompatibility or accidental authority coupling. The direct Shapes digest binds chain id, exact Shapes address, artist and release hash; tests reject wrong signer/hash/chain and cross-deployment replay, independently reconstruct the EIP-712 domain/digest, cover ERC-1271 including an empty valid signature, and prove an EIP-7702 delegated EOA can use its canonical ECDSA key. Neither `artist()` nor any attestation field is consulted by authorization or economic paths. Residual operational risk is the irreversible choice of release hash and the race created by issuing multiple valid signatures, carried in R4/D-05.
- R21 (mitigated 2026-08-27) Root frontend dependency audit initially reported 26 transitive advisories (3 high). Vite 6.4.3 and scoped Axios/WalletConnect `ws` overrides reduce the exact lockfile to 9 moderate and 0 high/critical findings; preview tests/build and Next lint/build pass. Residual: reassess the Wagmi 2 connector graph during the P2 mainnet-site release review; do not force a major wallet-stack migration without a concrete vulnerability or supported-network integration failure.
- R22 (closed 2026-08-27) Optional indexer availability/resource trust. The initial D-10 client could wait forever or follow unbounded hostile pagination before raw-chain fallback. Every page now has an 8-second abort and 256 KiB body cap; pages, items and cursors are bounded against current `totalSupply`, with deterministic chain fallback on every violation. Focused stalled/oversized/repeating-cursor tests pass.
- R23 (closed 2026-08-27) Server OG metadata fetch boundary. An RPC could previously forge `metadata.image` as an external URL for server rendering. The route now accepts only bounded `data:application/json;base64` metadata containing a bounded, passive `data:image/svg+xml;base64` image whose elements and references cannot initiate external loads. Canonical artwork plus malicious URL/active SVG regressions pass.
